# Interactive one-shot isolation (#570)

Status: **r3 inconclusive; PTY capability gate remains closed**. This spike follows brief v2, its CI-auth addendum and the r3 startup ruling. No HTTP default is introduced.

Local CLI: **2.1.304 (Claude Code)**. `claude --help` says `--no-session-persistence` only works with `--print`. The installed CI version and the argv captured at the actual supervisor spawn seam will be recorded by the opt-in integration suite.

## Evidence plan

The integration suite drives `runOnceOnPty` with `isolation: untrusted`, using a temporary HOME/config on GitHub Actions. The production capability gate is opened only within the test and restored afterwards. Nothing runs against a developer's real Claude configuration. The workflow alone supplies authentication through its existing secret-scoped environment; no test reads, copies or logs a credential.

| Property | Production control | Baseline / control-removed twin |
| --- | --- | --- |
| Tools | `--tools ""` | injection cannot create a marker or record tool_use / tools enabled with permission setup must create the marker |
| MCP | `--strict-mcp-config`, no config supplied | user-configured stub never starts / dropping strict mode starts it |
| Settings/hooks | `--setting-sources ""` | hook markers absent / dropping the source restriction writes one |
| Memory | source restriction, empty cwd | user CLAUDE.md canary absent / dropping source restriction reveals it |
| Commands, cwd, transcript | `--disable-slash-commands`, slash-input guard, fresh cwd, finally cleanup | command canary absent and temp artifacts removed / removing command controls exposes canary, bypassing transcript cleanup leaves JSONL |
| Environment | caller's print environment policy compared against real PTY child | irrelevant fake secret absent / deliberately admitting it makes the same check fail |

The probe code asserts the expected result for each direction. A baseline failure or a twin that cannot demonstrate leakage blocks rollout. Logs expose only canary booleans and sanitized status, never raw output or environments.

## Shared argv and print-only compensation

Both engines consume the single `UNTRUSTED_CLAUDE_ARGS` constant: `--tools "" --strict-mcp-config --setting-sources "" --no-session-persistence --disable-slash-commands`. The test captures actual supervisor spawn options and prints the exact built argv; a unit parity test catches missing flags/values. No flags are inferred from documentation alone.

Interactive transcript persistence must be treated as enabled even with the shared print-only flag. After the one-shot PTY is fully retired, cleanup removes the unique project's transcript directory under `CLAUDE_CONFIG_DIR` (or HOME/.claude), then removes the temporary cwd. A separate project directory is preserved. A control-removed twin disables that cleanup and must leave a real JSONL artifact.

## r3: supported interactive policy and environment correction

The coordinator ruled that the above was a startup blocker, not a red property. `UNTRUSTED_CLAUDE_ARGS` remains the only complete policy; `PRINT_ONLY_UNTRUSTED_ARGS` declares exactly `--no-session-persistence`, with its transcript-removal compensation named beside it. `untrustedInteractiveArgs()` derives the interactive argv by removing only that subset. Tests pin the exception list to that single flag and preserve all four critical interactive controls.

Local `claude --version` and `claude --help` checked again without authentication: **2.1.304**. `--tools`, `--strict-mcp-config`, `--setting-sources` and `--disable-slash-commands` are listed without a print-only restriction; no additional flag was dropped. Help confirms parser support, not runtime isolation; the real probes remain necessary.

The source-level environment gap was confirmed by a failing capture test: PTY ignored print's caller override and augmented its general environment with trusted provider values. It now uses the same caller environment as print for untrusted calls, without that augmentation. At the synchronous bun-pty FFI boundary it excludes every native/JS environment key not in the policy. Native `environ` is enumerated because a JS-deleted key can remain in libc; separate JS/native snapshots are restored even when the spawn throws. Failure to obtain native isolation fails closed. Trusted spawns keep their existing strip-list behavior.

A real local `/bin/sh` PTY test (no Claude/auth) seeds a harmless native-only canary, verifies that the child cannot inherit it, and verifies parent restoration. Full environment assertions/logs are avoided: only booleans are emitted. Missing policy forwarding and missing native enforcement each made their test fail before restoration.

Transcript cleanup also follows the caller's effective CLAUDE_CONFIG_DIR/HOME override. A unit regression first left the caller-root JSONL behind, then passed after cleanup was aligned with the child's environment policy.
