## Architecture decisions (frozen)

Decisions not to be re-litigated, each with its rationale.

1. **PTY turn evidence comes from the session transcript, never the screen.** The screen is never evidence that a prompt was accepted, that a turn finished, or of what the answer was. Only the session transcript is. The screen may be used for readiness, dialogs and liveness, and only to stop or fail a turn, never to mark it successful.
   Rationale: #559 and the #562 soak showed repaints, chunk splits, prompt echo and CLI chrome changes each producing a false success; the transcript-reading bus path went 99/99. Enforced by `src/__tests__/pty-turn-evidence-guard.test.ts`, which follows the module graph (round 3). A turn's outcome has three states from the transcript alone: running, finished OK, finished FAILED (API error, command stderr, uncertain attribution); the outcome is committed when the transcript establishes it and the screen only delays the return. "Established" means the transcript shows an authoritative boundary after the final message: the CLI's `turn_duration` record, or the next real user prompt (round 5). Nothing else ends a turn: not a quiet file (no inactivity timer) and not a progress, hook, attachment or other bookkeeping record, which neither close nor cut the final message (later lines of the same message id still extend the answer). Error records are read first: an API error anywhere before the boundary fails the turn. With no boundary by the turn's timeout the turn is UNCERTAIN (`PtyTranscriptUncertainError`): no answer, no replay. The answer is the FINAL assistant message by identity (message id), whether or not it has text: a textless final message is `empty reply in transcript`, never the narration before it (round 6). Error flags are read first on every assistant record whatever its shape. An id-less assistant line beside any other assistant line of the turn fails as uncertain (`ambiguous`). A reply with no text is a failure (`empty reply in transcript`), on every caller; `/compact`'s own output is exempt. (Operator ruling, Terry, 2026-10-21; boundary rule, kill-and-resume and empty = failure, Terry, 2026-10-22.)

2. **A turn that is not a proven OK kills the process and resumes the session.** Whenever a turn ends in anything but a proven OK (uncertain, prompt not accepted, ambiguous, transcript timeout, API error, replaced transcript, empty reply, a process that closed after the prompt went out), the supervisor retires the entry: it disposes the process, waits for it to have exited, and only then returns the error. No retry, no replay (a timeout is exit 124). The next call spawns a new process that `--resume`s the SAME session id, and not before the old one has exited. Only a process that was already gone before the prompt was written is retried.
   Rationale: the only writer that could append a late record for the failed turn is dead before any later turn marks its offset, so the transcript's exact payload match is safe without per-submission ids and the transcript reader keeps no memory of failed submissions (the round-4 "unresolved" registry, with its TTL and eviction, is gone). Pattern from ClaudeClaw-Ultra's PTY supervisor. Where it lives: `retireEntry` in `src/runner/pty-supervisor.ts`.
